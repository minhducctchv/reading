# 7.5 Profiling

Profiling helps you understand where your build is spending time. This allows you to find bottlenecks and optimize your Gradle build.

## Using `gradle --profile`

The `--profile` flag is a simple way to measure build performance. When you run a build with this flag, Gradle generates an HTML report.

You can use it like this:

```bash
gradle build --profile
```

After the build finishes, Gradle creates a report file. You can find this file in the `build/reports/profile` directory. Open the HTML file in a web browser to view the results.

The report shows you:
- How much time was spent on configuration.
- How much time was spent on each task.
- Which tasks took the longest time to run.

## Using Build Scans (`--scan`)

For more detailed information, you can use Gradle Build Scans. Build scans provide deep insights into your build performance.

You can run a build scan using the `--scan` flag:

```bash
gradle build --scan
```

When you use this flag, Gradle collects data about your build. It then uploads this data to a server. Finally, it gives you a link to view the detailed report online.

A build scan can help you see:
- Information about the build environment.
- Details about dependency resolution.
- Performance metrics for plugins and tasks.
- Suggestions for improving build speed.
