# 7.4 Incremental Build

Incremental build is a powerful feature in Gradle. It saves time by only running tasks that actually need to run. If a task's inputs and outputs have not changed, Gradle skips the task.

## How Incremental Build Works

Gradle tracks the inputs and outputs of every task. Before a task runs, Gradle takes a snapshot of its inputs. After the task finishes, Gradle takes a snapshot of its outputs.

When you run the build again, Gradle compares the new inputs and outputs with the previous snapshots. If nothing has changed, Gradle marks the task as `UP-TO-DATE`. This means the task is skipped.

## Task Inputs and Outputs

To use incremental build, you must define the inputs and outputs of your tasks clearly.

- **Inputs:** These are the files, directories, or properties that a task needs to do its job. Examples include source code files or version numbers.
- **Outputs:** These are the files or directories that a task creates. An example is a compiled `.class` file or a `.jar` file.

## Implementing Incremental Tasks

You can create custom tasks that support incremental build. You do this by adding annotations to your task properties.

Here are the most common annotations:

- `@Input`: Use this for simple values like strings or numbers.
- `@InputFile` or `@InputDirectory`: Use these for files or folders that the task reads.
- `@OutputFile` or `@OutputDirectory`: Use these for files or folders that the task creates.

### Example: A Custom Incremental Task

Here is a simple example of a custom task in Kotlin DSL. It reads a file and writes an output.

```kotlin
abstract class ProcessTextTask : DefaultTask() {

    @get:Input
    abstract val prefix: Property<String>

    @get:InputFile
    abstract val inputFile: RegularFileProperty

    @get:OutputFile
    abstract val outputFile: RegularFileProperty

    @TaskAction
    fun process() {
        val inputContent = inputFile.get().asFile.readText()
        val prefixText = prefix.get()
        val result = "$prefixText: $inputContent"
        outputFile.get().asFile.writeText(result)
    }
}
```

In this example, if the `prefix` or the `inputFile` changes, the task will run again. If the `outputFile` is deleted or modified, the task will also run again. If nothing changes, the task is safely skipped.

## Best Practices

Follow these rules to make sure incremental builds work correctly:

- **Always declare inputs and outputs.** If you forget to declare them, Gradle might skip the task when it should run, or run it every time unnecessarily.
- **Do not use absolute paths.** Use paths relative to the project. This helps when sharing the build cache with other developers.
- **Keep tasks pure.** A task should only depend on its declared inputs. It should not read hidden files or rely on external network state.
- **Avoid overlapping outputs.** Two different tasks should not write to the exact same output file or directory.
