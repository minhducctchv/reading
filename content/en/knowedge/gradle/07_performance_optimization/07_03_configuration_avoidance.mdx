# 7.3 Configuration Avoidance

Gradle has a feature called Task Configuration Avoidance. It helps your builds run faster.

## What is Configuration Avoidance?

When you run a Gradle build, it has a configuration phase. In this phase, Gradle looks at all the tasks in your project. Normally, Gradle configures every task. This happens even if you only want to run one task. 

Configuration Avoidance changes this. It tells Gradle to only configure the tasks that you actually need to run.

## Why Use Configuration Avoidance?

Configuring a task can take time. If you have a large project with many tasks, the configuration phase can be slow. By avoiding unnecessary configuration, you save time. This makes your overall build much faster.

## How to Use It

To use Configuration Avoidance, you need to change how you define tasks in your build scripts.

### Do Not Use `create()`

The `create()` method configures the task immediately. This is called eager configuration.

```kotlin
// Bad Example: Eager configuration
tasks.create("myTask") {
    // This code runs in every build
    println("Configuring myTask right now!")
}
```

### Use `register()` Instead

The `register()` method delays the configuration. Gradle will only configure the task when it is needed for the current build. This is called lazy configuration.

```kotlin
// Good Example: Lazy configuration
tasks.register("myTask") {
    // This code only runs when myTask is executed
    println("Configuring myTask only when needed!")
}
```

## Summary

Always use `tasks.register()` instead of `tasks.create()`. This simple change helps Gradle avoid unnecessary work. Your configuration phase will be much faster.
