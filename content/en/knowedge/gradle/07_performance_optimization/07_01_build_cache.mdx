# 7.1 Build Cache

The build cache is a powerful feature in Gradle. It saves the outputs of build tasks. When you run a task again, Gradle checks the cache. If the output is already there, Gradle reuses it. Gradle does not run the task again. This saves a lot of time and makes the build much faster.

There are two types of build cache: local cache and remote cache.

## Local Cache

The local cache saves task outputs on your own computer. This is very helpful when you clean your project or switch between Git branches. 

To turn on the local cache, you need to add a line to your `gradle.properties` file:

```properties
org.gradle.caching=true
```

You can also turn it on for a single build by using the command line flag `--build-cache`. The local cache is stored in the `.gradle/caches` folder in your user home directory.

## Remote Cache

The remote cache saves task outputs on a network server. This allows your whole team to share the cache. It is also very useful for Continuous Integration (CI) servers.

If a teammate or the CI server has already built a task, the output is saved to the remote cache. When you run the same task, Gradle downloads the output from the server. You do not need to build it yourself. 

To use a remote cache, you must configure it in your `settings.gradle` file. Here is a simple example:

```groovy
buildCache {
    remote(HttpBuildCache) {
        url = 'https://build-cache.mycompany.com/'
        push = true
    }
}
```

The `push = true` setting allows your computer to upload new outputs to the server. Usually, developers only download from the remote cache, while the CI server is the one that pushes to it.
