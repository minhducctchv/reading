# 8.2 Integration Testing

### Overview
Integration tests check how different parts of your application work together. Unit tests only check single parts in isolation. Integration tests make sure the whole system functions correctly. 

These tests often connect to a real database, a network, or a file system. Because of this, they are usually slower than unit tests.

### Separating Tests
It is best practice to keep unit tests and integration tests separate. 

Unit tests run very fast. Developers run them often while coding. Integration tests take more time. They are usually run before finishing a task or on a build server. Separating them gives you fast feedback from unit tests without waiting for slow integration tests.

### Setting up a New SourceSet
In Gradle, a `SourceSet` is a group of source files. By default, Gradle has a `main` source set for your application code and a `test` source set for unit tests. 

To create a separate place for integration tests, you add a new source set in your `build.gradle` file.

```groovy
sourceSets {
    integrationTest {
        java {
            compileClasspath += main.output + test.output
            runtimeClasspath += main.output + test.output
            srcDir file('src/integrationTest/java')
        }
        resources.srcDir file('src/integrationTest/resources')
    }
}
```
This tells Gradle to look for integration test code in the `src/integrationTest/java` folder.

### Configuring Dependencies
Your integration tests will need the same libraries as your unit tests. They might also need extra tools. You can share dependencies easily.

```groovy
configurations {
    integrationTestImplementation.extendsFrom testImplementation
    integrationTestRuntimeOnly.extendsFrom testRuntimeOnly
}
```
This configuration means your integration tests can use any library you added for your standard tests.

### Creating the Test Task
Gradle needs a specific task to run your new tests. You must register a new task of type `Test`.

```groovy
tasks.register('integrationTest', Test) {
    description = 'Runs integration tests.'
    group = 'verification'

    testClassesDirs = sourceSets.integrationTest.output.classesDirs
    classpath = sourceSets.integrationTest.runtimeClasspath

    // Make sure unit tests run before integration tests
    shouldRunAfter test
}

// Add it to the standard check lifecycle
check.dependsOn integrationTest
```

### Running the Tests
You can now run your integration tests using the command line.

```bash
./gradlew integrationTest
```
This command runs only your integration tests. It skips the normal unit tests.
