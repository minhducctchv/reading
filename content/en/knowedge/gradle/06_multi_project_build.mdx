# 6. Multi-Project Build

A multi-project build is a single Gradle build that contains many smaller projects. These smaller projects are called subprojects or modules.

This setup is very useful for large applications. You can break a big system into small, reusable parts. This makes your code easier to read, manage, and test.

## settings.gradle

The `settings.gradle` file is the starting point for a multi-project build. You must place this file in the root folder of your main project.

Gradle reads this file first. It uses this file to find all the subprojects. Without `settings.gradle`, Gradle will only build the root project.

## include modules

You use the `include` command inside `settings.gradle` to add subprojects. Each name you include becomes a module in your build.

For example, if you have a module named `core` and a module named `app`, you add this line to `settings.gradle`:

```groovy
include 'core', 'app'
```

Each included folder must have its own `build.gradle` file to define its specific build logic.

## shared configuration

Many modules often need the same settings. For example, they might use the same Java version or the same testing tools.

Instead of repeating code, you can share these settings. You put the shared settings in the root `build.gradle` file. 

You can use the `subprojects` block to apply rules to all modules. You can use the `allprojects` block to apply rules to the root project and all modules.

```groovy
subprojects {
    apply plugin: 'java'
    
    repositories {
        mavenCentral()
    }
}
```

## inter-module dependencies

Modules often need to use code from other modules in the same project. You can easily link them together.

You declare this link in the `dependencies` block. You use the `project()` command to point to another module.

For example, if the `app` module needs the `core` module, you add this to the `build.gradle` file of the `app` module:

```groovy
dependencies {
    implementation project(':core')
}
```

This tells Gradle that the `core` module must be built before the `app` module.

## composite builds

A composite build is an advanced feature. It lets you combine multiple independent Gradle builds into one single build.

This is very helpful when you develop an application and a separate library at the same time. Instead of downloading the published library, Gradle will build the library from your local source code.

You use the `includeBuild` command in the `settings.gradle` file to add a composite build:

```groovy
includeBuild '../my-independent-library'
```
