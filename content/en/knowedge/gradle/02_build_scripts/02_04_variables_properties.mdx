# 2.4 Variables & Properties

When you write a build script, you often need to store values. These values can be version numbers, file paths, or secret keys. Gradle provides different ways to declare and use variables. This helps keep your code clean and easy to maintain.

## ext {}

The `ext` block allows you to define custom variables in your project. These are called "extra properties". You can create them directly inside your build script.

This is very useful for sharing a value across your script. For example, you can define a library version once. Then, you can use that same version in multiple places.

```groovy
// Define the variable
ext {
    springVersion = "3.1.0"
}

// Use the variable later
dependencies {
    implementation "org.springframework.boot:spring-boot-starter-web:${springVersion}"
}
```

## gradle.properties

The `gradle.properties` file is a plain text file. It stores variables as simple key-value pairs. You usually create this file in the main folder of your project.

This file is excellent for setting global configurations. It is also a good place to put data that you do not want to mix with your build code. When you run Gradle, it automatically loads these variables for you.

**Inside gradle.properties:**
```properties
appVersion=1.0.0
useCache=true
```

## system properties

System properties are variables managed by Java or your operating system. You can pass these variables to Gradle when you run a command. You do this by using the `-D` flag in your terminal.

This method is perfect for temporary changes. For example, you might want to pass a specific environment name just for one build run.

**Command line example:**
```bash
gradle build -Denv=production
```

You can then read this value inside your build script using `System.getProperty("env")`.
