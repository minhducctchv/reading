# 4.3 Task Configuration

Task configuration is the process of setting up a task before it runs. Gradle executes the configuration code during the **configuration phase**. This phase happens before any task actions execute.

You use the configuration block to set properties for the task. You can also define what the task will take and produce.

## inputs / outputs

Gradle tasks usually process information. They take some data as **inputs** and produce new data as **outputs**.

For example, a compile task takes source code files as inputs. It produces compiled class files as outputs.

You must tell Gradle about these inputs and outputs. You can do this using the `inputs` and `outputs` properties of a task.

```groovy
task generateReport {
    // Define the input file
    inputs.file("src/data.txt")
    
    // Define the output file
    outputs.file("build/report.txt")

    doLast {
        println "Generating report..."
        // Code to read data.txt and write report.txt
    }
}
```

Defining inputs and outputs helps Gradle understand the flow of data in your project.

## incremental build

**Incremental build** is a powerful feature in Gradle. It saves time by skipping tasks that do not need to run again.

Gradle uses the `inputs` and `outputs` to decide if a task should run. Before running a task, Gradle checks its inputs and outputs.

If the inputs have not changed since the last build, Gradle checks the outputs. If the outputs are also unchanged, Gradle skips the task.

When a task is skipped, Gradle marks it as `UP-TO-DATE`. This makes the build process much faster.

If you do not declare the inputs and outputs, the task will always run. Therefore, it is very important to define them correctly.
