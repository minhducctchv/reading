# 3.3 Dependency Resolution

Dependency resolution is the process Gradle uses to find and download the libraries your project needs. 

Sometimes, different parts of your project might require different versions of the same library. Gradle has rules to solve these problems and build your project successfully.

## Conflict Resolution

A version conflict happens when your project asks for two or more different versions of the same dependency. For example, your code needs version 1.0, but another library requires version 2.0.

By default, Gradle solves conflicts by choosing the newest version. This rule is called "latest version wins". Gradle assumes that newer versions work well with older ones.

If you need a different version, you can change this behavior. You can force Gradle to use a specific version. You can also tell Gradle to fail the build when a conflict happens. This allows you to check and fix the issue yourself.

## Dependency Tree

A project usually has many dependencies. These dependencies often need other dependencies to work. The extra dependencies are called "transitive dependencies". 

Together, all direct and transitive dependencies form a structure. This structure is called the dependency tree.

You can view your project's dependency tree to understand what Gradle downloads. You can use the terminal to run the `dependencies` task:

```bash
./gradlew dependencies
```

Reading the dependency tree is very useful. It helps you see exactly why a library is included in your project. It also shows which version Gradle picked to resolve any conflicts.

## Exclusions

Sometimes, a transitive dependency can cause errors. It might be incompatible with your code, or you might simply not need it.

You can tell Gradle to remove a specific transitive dependency. This action is called an exclusion. When you exclude it, Gradle will not download that library.

You can add exclusions directly in your build script. You use the `exclude` keyword for this. You can specify the group name or the module name to exclude the exact library you want to remove:

```kotlin
dependencies {
    implementation("com.example:library-a:1.0") {
        exclude(group = "com.example", module = "bad-library")
    }
}
```
