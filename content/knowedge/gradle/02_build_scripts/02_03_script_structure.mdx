# 2.3 Script Structure

A Gradle build script generally follows a specific structure. It organizes different parts of the build process into blocks. Most build scripts use common blocks like `plugins`, `repositories`, `dependencies`, and custom tasks.

## plugins {}

The `plugins {}` block adds features to your project. Plugins provide pre-written tasks and settings. For example, the `java` plugin helps you compile Java code. This block must be placed at the top of your build script.

```kotlin
plugins {
    id("java")
    id("application")
}
```

## repositories {}

The `repositories {}` block tells Gradle where to find external libraries. External libraries are code written by other people that your project needs. Gradle downloads these libraries from the repositories you list here. Common repositories include `mavenCentral()` and `google()`.

```kotlin
repositories {
    mavenCentral()
    google()
}
```

## dependencies {}

The `dependencies {}` block lists the specific external libraries your project uses. You define what your project depends on to compile or run. Gradle uses the repositories to find and download these dependencies. You also specify how the dependency is used, such as `implementation` for main code or `testImplementation` for test code.

```kotlin
dependencies {
    implementation("org.springframework.boot:spring-boot-starter-web:3.1.5")
    testImplementation("org.junit.jupiter:junit-jupiter:5.10.0")
}
```

## tasks {}

Custom tasks are defined to perform specific actions. A task represents a single piece of work in the build process. Compiling code, running tests, or creating a ZIP file are examples of tasks. You can define your own tasks to automate custom jobs for your project.

```kotlin
tasks.register("hello") {
    doLast {
        println("Hello from Gradle!")
    }
}
```

This clear structure keeps your build script organized. It separates added features (plugins), library sources (repositories), required libraries (dependencies), and custom actions (tasks).
