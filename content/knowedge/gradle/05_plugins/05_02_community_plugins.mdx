# 5.2 Community Plugins

Community plugins are created by other developers or companies. They add extra features to Gradle. You can find them on the Gradle Plugin Portal. To use a community plugin, you must specify its ID and version in your `build.gradle` file.

## Spring Boot plugin

The Spring Boot plugin is a very popular community plugin. It helps you build and run Spring Boot applications easily.

This plugin does many useful things. First, it packages your application into an executable Jar or War file. Second, it allows you to run your application directly using a simple Gradle task. Third, it works tightly with Spring Boot's dependency management to control library versions.

To use this plugin, you add its ID to the `plugins` block. For example:
```gradle
plugins {
    id 'org.springframework.boot' version '3.2.0'
}
```

## Shadow (fat jar)

The Shadow plugin is used to create a "fat Jar". A fat Jar is a single Jar file that contains your application code and all of its required dependencies. This makes your application very easy to run and deploy anywhere.

Normally, a standard Jar file only has your own code. The Shadow plugin changes this. It collects all the necessary files from your external libraries and puts them inside one big Jar file. 

To use the Shadow plugin, you add its ID. For example:
```gradle
plugins {
    id 'com.github.johnrengelman.shadow' version '8.1.1'
}
```

## Docker plugin

There are several Docker plugins for Gradle. They help you build and publish Docker images. A Docker image contains your complete application and everything it needs to run inside a container.

These plugins let you build Docker images directly from your Gradle build. A popular choice today is the Google Jib plugin. Jib is special because it builds optimized Docker images for Java applications, and you do not even need to write a `Dockerfile`.

For example, to use the Jib plugin:
```gradle
plugins {
    id 'com.google.cloud.tools.jib' version '3.4.0'
}
```
